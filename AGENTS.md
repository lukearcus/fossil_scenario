# AGENTS.md

Data-driven neural certificate synthesis tool (scenario approach). Fork/extension of FOSSIL. Python research codebase; no CI, no test suite, no linter.

## Environment

- Conda env name is `neural`. Create with `conda env create -f environment.yml` then `conda activate neural`.
  - README says `conda env create -f requirements.txt` — that file does not exist; use `environment.yml`.
  - `setup.py` targets py3.9+; the shipped env uses Python 3.12 + CPU-only PyTorch. Don't swap in GPU/CUDA torch without checking `environment.yml`.
- dReal and cvc5 verifiers need external install (not pip-only). See the `dreal` prereq script invoked in `Dockerfile`. Z3 (`z3-solver`, pip) is the default and needs no extra setup.
- `pip install .` registers the `fossil` console script (entry point: `fossil.main:_cli_entry`).

## Running benchmarks

- Correct invocation: `python3 -m experiments.benchmarks.barr_1_alt` (run from repo root so the `experiments` package imports).
  - README's `experiments.scenapp_tests.benchmarks.barr_1_alt` is stale — there is no `scenapp_tests` directory.
- **Known broken imports**: several files under `experiments/benchmarks/` still contain `from experiments.scenapp_tests.benchmarks import models`, which does not exist. Fix the import to `from experiments.benchmarks import models` (or `from experiments.barr... import models`) before running those files. The files in `experiments/barr/` already use the correct path.
- Common flags (parsed in `fossil/main.py:run_benchmark`): `--plot` (2D only), `--record` (CSV), `--repeat N`, `--concurrent`.
- `synthesise()` and `run_benchmark()` force `torch.set_num_threads(1)`. Don't assume multi-threaded torch.
- Output artifacts: `plots/`, `results/`, `nice_results/`, and `*.e*`/`*.o*` PBS job files (e.g. `fossil_test_mild_unstab.*`) are generated by runs / HPC. Many are git-tracked despite looking like build artifacts; check before assuming they're disposable.

## CLI / YAML configs

- `fossil <config.yaml>` runs synthesis from a YAML config (parsed in `fossil/cli.py`).
- `fossil --certificate BARRIER` prints the symbolic + data sets required for that certificate, then exits. Useful before writing a config.
- `fossil --plot` plots at the end (2D only). `-v 0|1|2` controls verbosity.
- `config.yaml` at repo root is currently empty — it is not a working example.

## Architecture

- `fossil/` is the library. `experiments/` holds runnable benchmark scripts (each defines a system + sets + `ScenAppConfig` and calls `fossil.synthesise` or `ScenApp(...).solve()`).
- `fossil/scenapp.py`: `ScenApp` — the main scenario-approach CEGIS-style loop. `fossil/main.py:synthesise` is the canonical entry point.
- `fossil/certificate.py`: loss functions and per-certificate training logic. (README/user-guide call it `certificates.py` and `CegisConfig` — both names are stale; the real class is `ScenAppConfig` in `fossil/consts.py`, and the file is `certificate.py`.)
- `fossil/consts.py`: all enums (`CertificateType`, `ActivationType`, `VerifierType`, `TimeDomain`, `DomainNames`) and the `ScenAppConfig` dataclass. This is the source of truth for config fields, not `user-guide.md` (which is partially out of date, e.g. field numbering and some defaults).
- `fossil/cli.py`: YAML → `ScenAppConfig` parsing, including per-certificate domain/data auto-adjustment (e.g. `adjust_rwa` derives XU as `XD \ XS`).
- `fossil/domains.py`: set construction (`Rectangle`, `Sphere`, `Union`, `SetMinus`, ...). See `set_guide.md` for which sets each certificate requires/rejects.

## Conventions / gotchas

- Passing a redundant symbolic set to a certificate raises an error by design — only pass the sets listed in `set_guide.md` for that certificate. Border sets (e.g. `XS_BORDER`, `XG_BORDER`) are auto-generated; do not specify them explicitly (data counts can still be given).
- Certificate naming differs subtly from upstream FOSSIL: this repo uses `BARRIERALT` (alt barrier), `RWA`/`RSWA`/`RWS`/`RSWS` (reach-while-avoid variants), `RAR`, `STABLESAFE`. Discrete-time supports only `LYAPUNOV` and `BARRIERALT`.
- `dReal`-only activations: `TANH`, `SIGMOID`, `SOFTPLUS`, `COSH`. `RELU` is discrete-time only.
- Models subclass `fossil.control.DynamicalModel` (or `_ParsedDynamicalModel` via YAML) and implement `f_torch` (tensor) and `f_smt` (symbolic) plus optionally `init_state_dist`. See `example.py` and `experiments/benchmarks/models.py`.
- There are leftover `build/` (stale installed copy of `fossil/`) and `Fossil.egg-info/` tracked in git — do not edit these; edit sources in `fossil/`.
- Stray vim `.swp` files exist under `experiments/`; ignore them.

## Verification

There is no automated test/lint/typecheck. To verify changes, run a small benchmark end-to-end, e.g.:
`python3 -m experiments.benchmarks.barr_1_alt --plot` (after fixing the stale import noted above).
For HPC, `test.pbs` shows the pattern: `module load miniforge/3 Python`, `conda activate neural`, run a `-m experiments.*` module.
